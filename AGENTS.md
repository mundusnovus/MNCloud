# Asteria Cloud and Asteria Office: brief for the agent building them

Read this whole file before you start. It is the same in both repositories (Asteria Cloud and Asteria Office).

## Asteria Technology in one paragraph

Asteria Technology makes free, open-source software and hosts it free: **good tools, freely given**. Its mission
comes from a Christian Unionist conviction that good tools belong in every hand, but the products leave religion out:
no religious symbols, words or verses in the brand or the apps. Everything lives under https://github.com/mundusnovus
(the org and repository names are still the old ones; the owner renames them later). It has **Asteria Sprite** (pixel
art), **Asteria Box** (music, built on BeepBox), **Asteria Social** (on the AT Protocol), **Asteria Learn**, and the
website, in **MundusNovusOrg**, on Railway at asteria.technology with subdomains sprite., box., social., cloud.,
office. and learn. One **Asteria account** signs people in everywhere.

**asteria.technology is the open side**: everything here is open source and free. **asteria.llc** is the commercial
side, which sells things made with the open tools (songs, ringtones, original apps, and later hardware). Never put
paid features or proprietary code in these repositories; the license lets people own and sell what they make with
the tools, and that is how the commercial side works too.

The brand: the mark is a folded A (one teal ribbon up the left leg, over the top and down the right, the right leg
in a deeper shade) with a gold four-pointed star in its heart: Asteria is the goddess of the stars. It is vector art,
sharp at any size. Each app icon is a dark tile with the app's own sign and a small gold star. Palette: teal
`#1c8c9e` (bright `#3bb3c3`, deep `#116674`), gold `#e9b04b`, ink `#0a1518`, parchment `#f4ecdb`. Everything is
generated by `MundusNovusOrg/brand/build_brand.py` (SVG first; PNG, .ico and .icns rendered on a Mac by
`render_svg.swift`) and copied into the apps by `MundusNovusOrg/tools/sync_brand.py`.

## What to build

1. **Asteria Cloud** (repo: MNCloud) at **cloud.asteria.technology**: the file hub for every Asteria
   Technology app. **An original service** (Node 24, no packages), not Nextcloud: the owner did not want Nextcloud's
   interface, so Nextcloud is only the example of how to do the job. Cloud speaks Nextcloud's protocols (Login Flow
   v2, WebDAV, chunked uploads, OCS capabilities) so its desktop client and the app connectors work with it.
   - Every account gets **3 GB** automatically. The whole service is capped at **256 GB** for now (paid tiers later;
     build free only).
   - **The PDS is part of sharing.** Contacts are your friends on Social (mutual follows first). Every share with a
     person is written to the sharer's PDS as an `technology.asteria.cloud.share` record through Social's service
     API, and the person gets a Social notice. Links anyone can view are also possible.
   - Sprite and Box can save to Cloud (automatically if the person turns that on). Office documents live in Cloud.
   - A **native desktop sync app** for Windows, macOS and Linux: a rebranded build of Nextcloud's desktop client
     (https://github.com/nextcloud/desktop, GPL-2.0-or-later, so it can use the Asteria License).
2. **Asteria Office** (repo: MNOffice) at **office.asteria.technology**: documents, spreadsheets,
   presentations and PDFs, built on **Euro-Office** (https://github.com/euro-office, AGPL-3.0; a fork of ONLYOFFICE).
   - A cloud editor (Euro-Office **DocumentServer**, image `ghcr.io/euro-office/documentserver`) that Asteria Cloud
     opens directly (`src/office.mjs` in Asteria Cloud).
   - A portal at office.asteria.technology: new document, recent documents from Cloud, templates.
   - A **native desktop app** for Windows, macOS and Linux: a rebranded, improved build of Euro-Office's desktop
     editors (`euro-office/desktop-apps`, `DesktopEditors`, `desktop-sdk`, `core`).

The owner decided: **full native desktop apps** built by **GitHub Actions** in these two repositories, and **an original Cloud
service** with its own web interface (Nextcloud's design is only the example).

## Rules from the owner

- **Use only these two repositories** (Asteria Cloud, Asteria Office) plus MundusNovusOrg, Asteria Sprite and
  Asteria Box where integration needs it. Do not fork upstream projects into new repositories: pin an upstream
  version (commit or image digest) in a lock file and keep our changes as patches, a theme, an app or build
  scripts, the way Asteria Box pins BeepBox (`MNBox/src/beepbox.lock.json`, `src/patches/`). If you truly
  need another repository, stop and ask the owner to create it.
- **Rebrand completely, as far as the licenses allow**: names, logos, icons, colours, fonts, About text. Keep every
  upstream copyright notice and license file. Nextcloud's and ONLYOFFICE's names and logos are trademarks: remove
  them from the interface, but credit the projects in About and NOTICE. Euro-Office removed ONLYOFFICE's
  "keep the logo" clause; its files carry only a copyright line, which must stay.
- **Improve, don't only rebrand.** The interfaces must match Asteria Technology quality: calm, fast, accessible
  (keyboard, screen readers, reduced motion), light and dark, responsive down to phones.
- **Design philosophy:** show, don't tell (and never say so). Not loud, not cheesy, not corny. Leave
  religion out of the products. Plain, short sentences.
- **Fonts:** use **Asteria Pixel** (our pixel display face) throughout the apps. In Office, **Asteria Pixel is the default
  interface font**, and the **default writing font is "Asteria Serif"**: a new, readable serif in the style of
  Times New Roman (the owner chose the name). Make it by renaming a metric-compatible open font such as
  **Liberation Serif** (SIL OFL 1.1: its Reserved Font Name "Liberation" must be dropped, so renaming is required
  and allowed); keep it under the OFL with a FONTLOG, and set it as the default font for new documents. Asteria Pixel's
  source and builder: `MundusNovusOrg/brand/font/` (`asteria-pixel-glyphs.json`, `build_font.py`).
- **Licenses:** our default is the **Asteria License 1.0** (`MundusNovusOrg/LICENSE`, the GPL-3.0
  text unchanged plus a nonbinding Christian Unionist statement). Work derived from AGPL code uses the
  **Asteria Affero License 1.0** (the `LICENSE` in these two repositories: AGPL-3.0 unchanged plus the same
  statement). Any other license that is not GPLv3-compatible gets its own Asteria Technology edition in the same
  pattern. AGPL means a public, hosted, modified version must offer its source to users: link the exact source in
  every About box and footer.
- Never commit secrets. Railway holds them.

## Accounts: one Asteria account

Accounts live in Social (`MundusNovusOrg/social/app.mjs`) on the PDS. Every asteria.technology address
answers `/api/` (`/api/me`, `/api/login`, ...), and the sign-in cookie covers the whole domain.
**Add an OpenID Connect provider** to `MundusNovusOrg` (for example `social/oidc.mjs`, served at
`https://social.asteria.technology/oauth/...` with discovery at `/.well-known/openid-configuration`): authorize
(send people to `/signin?return=...` if not signed in), token, userinfo, JWKS, RS256 keys kept in `DATA_DIR`,
first-party clients configured by environment. Cloud signs people in with it (user id = Social name), and so does the desktop sync app's browser login.
Add tests in `MundusNovusOrg/test/` (`node --test test/*.test.mjs`, Node 24, no packages).

## Asteria Cloud: how it fits together

- **Server** (`src/`, Dockerfile here): `node:24-slim`. File contents in the **Railway storage bucket** (S3 API,
  prefix `cc/`); the file list, shares, versions and sessions in SQLite on the `/data` volume. Space is checked in
  the same transaction that records a file, so the 3 GB quota and the 256 GB cap always hold.
- **Sign-in**: OpenID Connect against Social (client `asteria-cloud`). The user id is the Social name.
- **Social service API** (`MundusNovusOrg/social/app.mjs`, `/api/service/...`, header `x-cs-service` =
  `SERVICE_SECRET` on both services): person, contacts, cloud-share (writes the PDS record and the notice) and
  cloud-unshare.
- **Web app** (`public/`): files, folders, upload (drag and drop), rename, move, copy, trash, versions, search,
  recent, shared with you, share sheet with Social contacts, links, devices. Opens documents at `/edit/<id>`.
- **Office**: Cloud signs the editor config with `OFFICE_JWT_SECRET`; the document key is `<id>-<etag>`, so everyone
  on the same version edits together; saves come back through a signed callback and become a new version.
- **Desktop sync app** (`desktop/`): branding for `nextcloud/desktop` plus `.github/workflows/desktop.yml`.

## Asteria Office: how it should fit together

- **Server image** (Dockerfile in Asteria Office): `ghcr.io/euro-office/documentserver`, pinned, with our branding
  applied (title, loader, favicon, About, editor colours and fonts, Asteria Pixel for the interface, Asteria Serif
  installed and set as the default for new documents), JWT secret from Railway, and our **portal** replacing the
  welcome page at `/`. The document server needs about 2 to 4 GB of memory.
- **Cloud** opens documents itself (`MNCloud/src/office.mjs`): it signs the editor config with the same JWT
  secret and receives saves through a signed callback. No connector app is needed.
- **Desktop app** (`desktop/`): branding and patches for Euro-Office's desktop editors, built for Windows, macOS
  and Linux by GitHub Actions (reuse Euro-Office's own build scripts and `release` automation where you can), able
  to connect to Asteria Cloud.

## Sprite and Box

Add **Save to / Open from Asteria Cloud** and an optional **autosave to Cloud**, through `as-host.js` so both apps
get it: connect with **Login Flow v2** (Nextcloud's protocol, which Cloud speaks) (app password kept on the device), then WebDAV into
`/MNSprite/` and `/MNBox/`. The desktop builds of Sprite and Box (`MundusNovusOrg/tools/package/`)
use the same code. Keep each app's tests green (`node --test src/test/*.test.js`).

## The website

Add Cloud and Office to asteria.technology: navigation, home page, `/downloads/` (the downloads list is
`site/downloads/files/downloads.json`, made by `tools/package/package.py`; add the GitHub release downloads for the
new desktop apps), and the source page. Pages are generated by `tools/pages.py` and `tools/build.py`.

## Hosting (Railway)

Project **"Asteria Technology"** (id `56ce7528-37c8-4d32-9708-98df2a03ca0e`), environment `production`. It has `web`
(MundusNovusOrg), `pds`, `cloud` (Asteria Cloud's Dockerfile, volume at `/data`), a storage bucket and

## Order of work, and what done means

1. Cloud and Office faces in `build_brand.py`; Asteria Serif built and licensed. Done: icons at every size, fonts load.
2. OIDC provider in MundusNovusOrg with tests. Done: a test client completes the code flow.
3. Cloud server boots locally (or on Railway) with a bucket, OIDC sign-in, 3 GB quota and the 256 GB cap.
4. Our Cloud web app: browse, upload, download, rename, move, delete and restore, share links, quota bar, search.
5. Office server with branding and portal; documents open and save from Cloud; co-editing works.
6. Sprite and Box save to Cloud.
7. Desktop workflows produce installers for both apps on all three platforms.
8. Website, downloads, deployment, DNS records.
